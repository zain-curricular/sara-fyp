# Phase 4 — Demo Data & Storage Seeding

> **PR 4** · **Depends on:** Phases 1, 2, 3 (final schema, gates, embedding path) · **Unblocks:** P5.
> **Goal:** one command — `npm run seed:demo` — fills a freshly-reset local Supabase with a production-feeling dataset: 50 sellers each with 10+ real image-bearing listings, 80 buyers, 10 mechanics, 3 admins, 300+ orders spanning every status, payouts, reviews, conversations, notifications, disputes, fraud signals, mechanic requests, and KB — all sourced from committed, license-safe data in `supabase/seed-data/`, with images uploaded into Supabase Storage. ## Task 4.1 — Media acquisition pipeline

### What it is
A curated, license-safe image set fetched once and committed, so seeding never needs the network.

### Current state (verified)
- `supabase/seed.sql` seeds text only — no images in storage; `20260419000010_storage_buckets.sql` defines 6 buckets with RLS. `supabase/seed-data/` and `scripts/` **do not exist**.

### Implementation approach
1. Author `supabase/seed-data/manifest.json` — a curated list of image URLs (part photos across engine/brakes/suspension/electrical/body/filters/cooling/fuel + avatars + store logos) from **license-safe sources only** (Wikimedia Commons, Unsplash/Pexels free tiers, permitted press kits), each with `{url, bucket, path, license, attribution}`.
2. `scripts/fetch-seed-media.ts` (`npm run seed:media`): downloads each URL, normalizes to ≤1600px JPEG, writes to `supabase/seed-data/media/<bucket>/<path>`, records checksum; skips already-present files.
3. `seed-data/sources.md` auto-generated from the manifest for attribution/licensing.
4. Commit the downloaded media (target ≥120 part/car + 50 avatar/logo images).

### Code changes
| File | Change |
|---|---|
| `supabase/seed-data/manifest.json` | new — curated URL list |
| `scripts/fetch-seed-media.ts` | new — downloader/normalizer |
| `supabase/seed-data/media/**` | new — committed images |
| `supabase/seed-data/sources.md` | new — attribution |
| `package.json` | edit — `seed:media` |

### Folder structure (this task)
Exactly the tree in [INDEX §2](INDEX.md#2-target-artifact-tree-canonical).

### Comment conventions (this task)
Script header states the license policy and that output is committed.

### Acceptance criteria
- [ ] `npm run seed:media` produces ≥170 committed images organized by bucket; re-run is a no-op
- [ ] Every image has a license + attribution entry in `sources.md`
- [ ] `npx tsc --noEmit && npm run lint` green

### Testing criteria
- **Engineer:** run once, count files per bucket, re-run and assert zero new downloads.
- **Non-technical:** Success = "the app has real car-part photos, all properly licensed, stored in the project."

## Task 4.5 — Seed runner (`npm run seed:demo`)

### What it is
The one command that loads all of the above into DB + Storage, idempotently, safe to run after any `supabase db reset`.

### Current state (verified)
- `supabase/seed.sql` runs on reset but is SQL-only (no storage upload); `scripts/seed-demo.ts` **does not exist**; service-role key documented as needed (`NOTES.md`).

### Implementation approach
1. `scripts/seed-demo.ts`: service-role Supabase client → (a) create auth users/identities, (b) upsert all JSON datasets in FK order with `ON CONFLICT` on deterministic UUIDs, (c) upload `seed-data/media/**` into the matching buckets and set image/avatar/logo rows, (d) trigger-disable around listing-limit like `seed.sql` does.
2. Optional embedding backfill call (3.3) when `OPENAI_API_KEY` present.
3. `package.json`: `seed:demo` (and keep the base `supabase:reset` SQL seed for minimal data). Fully re-runnable.

| `scripts/seed-demo.ts` | new — orchestrator |
